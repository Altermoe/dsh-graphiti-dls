# 实施与实验报告

> 日期：2026-11-13 · 状态：README 的 P0 最小闭环已落地，对比实验与消融实验已跑通。
> 本文中的文件路径均相对仓库根目录。
> 原始结果：`eval/results/compare.json|md`、`eval/results/ablation.json|md`。

## 一、结论先行

1. **DLS 全量在 60 个角色扮演长期记忆 case 上全面领先**：事实回忆准确率 100%、状态更新精确率 100%、时态查询准确率 100%，过期事实误用率 / 错误记忆写入率 / 注入持久化率 / 攻击成功率均为 0%。最强对照（原生 Graphiti）回忆准确率 80%，但状态更新 0%、错误写入 100%、攻击成功率 100%。
2. **收益不是来自「用了图谱」，而是来自图谱之上的规则层**。原生 Graphiti 已具备双时态能力（时态查询 100%），但缺少写入策略、状态规则、作用域隔离与预算编译，安全指标全线失守，决策变更精确率为 0%。这直接支持 README「DLS 的价值通过与原生 Graphiti 的对照实验验证」的判据。
3. **消融实验把收益归因到具体组件**：双时态与失效（状态更新 100%→0%）、写入策略（错误写入 0%→66.7%）、作用域隔离（准确率 100%→70%）、上下文编译（高负载注入量 93→1371 tokens，14.8×）、审计纠错（准确率 100%→90%）。
4. **存在防御纵深，单层消融会被其他层补偿**。来源降权是唯一单层关闭后指标不变的组件：写入阶段已拦截低信任内容，排序层因此显得「无用」。组合消融（同时关闭写入策略 + 隔离 + 来源降权）使错误写入率升至 100%、准确率降至 70%，确认这是补偿关系而非冗余设计。
5. **代价可量化**：DLS 为每条事实保留来源、信任、状态与时间标记，平均输入 84 tokens（对照 33~85）；但在 40 条无关记忆的高负载下，预算编译把注入量压到 93 tokens，仅为全量注入型社区插件 `dsh-aiyayi`（385 tokens）的约 1/4。

关键发现：

- **所有对照方案的错误记忆写入率与注入持久化率都是 100%**——它们把候选事实当作已确认数据直接持久化，没有来源校验、关系白名单或指令/权限识别。这是 DLS 与社区插件最大的分野。
- `@dsh-agentic-roleplay/state` 的攻击成功率为 0%，但注入持久化率仍为 100%：它的精确 `recall`（按主体 + 关系过滤）恰好把攻击载荷排除在上下文之外，属于**结构性副作用**，不是安全策略。一旦查询命中该关系，攻击内容仍会被使用。
- 原生 Graphiti 是唯一在时态查询上达到 100% 的对照，印证时态能力属于图谱底座；但它的「当前状态视图」缺失，决策变更类全部答错（0%）。
- 滚动摘要在「决策变更 / 删除 / 过期事实」类上得分不低，是因为它把细节压没了、答案常为空；**必须结合事实召回率（12.5%）一起读**，见「已知偏差」。

## 四、消融实验

完整表格见 `eval/results/ablation.md`。各变体相对 DLS 全量的退化（百分点 / 倍数）：

| 关闭的组件 | 主要受损指标 | 解读 |
|---|---|---|
| 写入策略（Schema/来源/白名单） | 错误写入 0%→66.7%，攻击成功率 0%→50% | 指令型内容、权限声明与低信任来源直接进入记忆状态 |
| 双时态与失效 | 状态更新 100%→0%，时态查询 100%→0%，过期误用 0%→100% | 旧决策不再失效、历史时间点失准、过期事实复活 |
| 作用域隔离 | 回忆准确率 100%→70%，错误写入 0%→33.3% | 跨用户事实泄漏进当前上下文 |
| 来源降权 | 无变化 | 写入阶段已拦截低信任内容，排序层被防御纵深补偿 |
| 上下文编译与预算 | 高负载注入 93→1371 tokens（14.8×），回忆准确率 100%→80% | 全量注入把失效/待确认事实一并带入；成本 0.002171→0.005174 USD |
| 冲突与纠正判断 | 状态更新 100%→0%，过期误用 0%→50% | 不再区分纠正、补充与矛盾，旧状态与新状态并存 |
| 审计与纠错（删除/撤销） | 回忆准确率 100%→90% | 删除请求不执行，被撤销事实仍可回忆 |
| 组合：写入策略 + 隔离 + 来源降权 | 准确率 100%→70%，错误写入 0%→100%，注入持久化 0%→100% | 证实三层之间是补偿关系，单层消融会低估风险 |

结论：README 中「上下文编译、状态规则与安全策略」三项新增复杂度，在本评测集上都有可测量的独立贡献；只有来源降权的贡献需要组合消融才能显现。

## 六、已知偏差与限制（务必阅读）

1. **「答不出反而算对」偏差**：删除与撤销、过期事实两类 case 以「不泄漏」为判定条件，任何返回空答案的系统都会得分。滚动摘要在这些 case 上的高分必须与其 12.5% 的事实召回率合并解读；后续应引入「选择性回答」指标（该答的答对、不该答的拒答）。
2. **评测隔离了抽取与生成质量**：所有系统面对相同的预标注候选事实流，答案由统一确定性 answerer 从进入上下文的结构化事实投影。因此结论适用于「记忆生命周期 + 上下文编译层」，不等于端到端对话质量。接入真实模型后需重跑回归。
3. **社区插件是机制等价适配器**：依据 dshmarket 官方目录描述复现其记忆策略，不是插件二进制直跑（真实插件是 DSH Web/Desktop 端完整应用，含 GUI、定时任务与平台特定依赖，无法在统一 headless 协议里驱动）。因此结果是「机制层面」的对照，不评价插件的工程完整度。
4. **攻击成功率是代理指标**：定义为「攻击内容进入模型可见上下文且未被标记为不可信」。README 要求区分「输出未暴露攻击内容」与「攻击确实未影响系统行为」，后者需要端到端工具执行环境，本次未覆盖。
5. **Token / 延迟 / 成本是估算**：Token 用确定性近似（CJK 1 token/字，其余 4 字符/token），延迟为进程内 `ingest+compile` 耗时（P50/P95 均在 0.2ms 以内），不含网络、图数据库与模型推理；成本按示例单价折算，只用于相对比较。
6. **`no_source_ranking` 无退化不等于组件无用**：见「防御纵深」；单层消融在多层安全架构中天然会低估贡献。
7. **本地 dsh 集成只验证到配置合成层**：`pnpm dsh --profile web --patch ... --dump-config` 通过，插件行为由单元测试覆盖；未完整 boot（需要把本仓库 link 进 profile 并配置模型凭据）。详见 `eval/results/dsh-integration.md`。
8. **知识图谱导航未使用**：本地 WSL 的 deepseek-harness 副本没有 `.ua/knowledge-graph.json`，架构结论全部回到 `docs/*.zh.md` 与 `packages/**/src` 源码复核。若后续用图谱导航，需注意三个已知盲区：barrel 再导出不可见（`rdeps` 为空不代表没依赖）、切片外依赖不可见（`client.ts` 的 `@deepseek-ai/dsh-api-*` 边缺失）、`preset/agent-preset/skills/` 下的文档会被误分入专用层。

## 七、复现

```bash
# 依赖（pnpm 11：构建脚本白名单在 pnpm-workspace.yaml）
pnpm install

# 静态与行为验证
pnpm run typecheck
pnpm run test                # 22 个用例

# 重新生成评测集、原始结果与报告
pnpm run eval:compare
pnpm run eval:ablation
pnpm run eval:all

# 抽查单个 case / 某类场景
python3 scripts/inspect_results.py ablation recall-0
python3 scripts/inspect_results.py compare cross_session_recall

# 重新采集 dshmarket 下载量与选型
python3 scripts/market_catalog.py --fetch --downloads \
  --select "dsh-fish-soul,dsh-aiyayi,dsh-cross-memory,@dsh-agentic-roleplay/state"

# 本地 dsh 集成验证（配置合成层）
pnpm run dsh:integration
```

所有评测产物均为确定性生成，重复执行应得到相同指标（时间戳除外）。
